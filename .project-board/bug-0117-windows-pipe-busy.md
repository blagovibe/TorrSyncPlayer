## Суть

`dial_windows.go` открывал именованный канал mpv одним вызовом
`syscall.CreateFile` и сразу возвращал любую ошибку. Именованный канал отдаёт
клиентам по одному экземпляру за раз, и Windows отвечает на лишний запрос
мгновенным `ERROR_PIPE_BUSY` («All pipe instances are busy»), а не «подождите».
Go внутри себя этот ответ ждёт — у его собственных каналов есть такая
ретраительная петля, — но написанный вручную `CreateFile` ждать не умеет.

Поймал `Test Frontend (windows-latest)` на коммите релиза v0.3.2:
`TestRealMpvOpensItsSocket` и `TestRealMpvListsAndSwitchesTracks` упали с
`player: open pipe torrsync-position-5740: All pipe instances are busy` и
`...torrsync-tracks-5740...`. Оба теста проходили на всех предыдущих прогонах.

## Почему это не только про тесты

Окно опрашивает mpv несколько раз в секунду, и каждый опрос — своё
соединение (`request` открывает канал на команду и закрывает его). На Linux
`net.Dial` просто соединяется, и гонки нет. На Windows канал может быть ещё
не отпущен предыдущим, и опрос возвращает не позицию, а ошибку — а позиция,
по словам самого `request`, должна быть настоящей: иначе буфер-репортер
отдаёт комнате начало фильма.

То есть ошибка наблюдаема и в приложении, не только в тестах; в тестах она
просто оказалась первой, потому что CI гоняет живые mpv-тесты на всех трёх
платформах.

## Обсуждение

2026-10-17: Найдено CI на коммите релиза v0.3.2, то есть уже опубликованного.
Тесты гоняются и на Windows — это и поймало.

Сделано: `dial` ждёт занятый канал — до двух секунд, по 100 мс, ровно как Go
делает это для своих каналов. Повторяется только «занято»: отсутствующий канал,
отказ по имени и мёртвый mpv возвращаются сразу, потому что ожидание их не
лечит, а только задерживает внятную ошибку.

Логика вынесена в `retry.go` без build-тега: только у Windows есть канал, а
вопрос «пробовать ещё или сдаться» — общий, и его видно на всех трёх
платформах. Четыре теста закрывают решения: дождаться занятого, не ждать
не-занятого, сдаться и не ждать впустую.

Проверено: локально на Linux; на Windows сборка пакета проходит
(`GOOS=windows go build ./internal/player`), а end-to-end проверка — это
windows-джоба CI, та же самая, что упала. Карточка открыта до зелёного CI.
