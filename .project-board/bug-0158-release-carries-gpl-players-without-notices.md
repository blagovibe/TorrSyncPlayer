## Суть

Все три релизных артефакта содержат сторонний плеер целиком:
`release.yml` копирует `mpv` в AppImage (`:60`, `:105–115`), в Windows-zip
(`:201–219`) и в macOS-бандл (`:290`), и README обещает «mpv уже внутри».
mpv распространяется под GPLv2+ (в сборках с ffmpeg — тоже GPL-компоненты), а
распространение таких бинарников требует как минимум текста лицензии и доступа
к исходникам (или письменного предложения).

В репозитории для этого нет ничего: поиск по `GPL|LGPL|THIRD|NOTICE|source
offer` даёт только упоминания сторонних GitHub Actions в журнале. `.github/`
содержит SECURITY.md, но не NOTICE; в релизных ассетах только SHA256SUMS.

Пока релиз — MIT-проект, в который положены GPL-бинарники; это не отменяет
распространение, но обязывает возить с собой чужие лицензии и исходники.
Риск не технический, а юридический, и он растёт с каждой скачанной сборкой.

## Обсуждение

2026-10-23: Найдено аудитом. Проверено чтением `release.yml`, README и поиском
по репозиторию. Лечение: `THIRD_PARTY_NOTICES` с лицензиями mpv/ffmpeg и
ссылкой на исходники в каждом артефакте, `mpv --version` в README/релизных
заметках, шаг релиза, который проверяет наличие файла в ассетах; проверить
условия конкретных сборок mpv (choco, brew, apt) у каждого канала.
