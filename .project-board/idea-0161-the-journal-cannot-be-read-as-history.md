## Суть

`CHANGELOG.md` смешивает два поколения истории: сверху `[Unreleased]` в формате
v0.4.x, ниже — разделы `v1.1.5` (2026-07-12), `1.0.0` (2025-06-01),
`v1.2.0-rc.6`, версии, тегов которых в репозитории нет (теги — `v0.1.0`…`v0.4.1`).
Файл заканчивается записью, которая старше верхних, а последняя строка —
«Проверено: …» из середины истории. Из журнала нельзя понять, где кончается
проверенное и начинается непроверенное, — а методология держится ровно на этой
границе.

Второе: запись v0.4.1 говорит «pipeline is green in full», а прогон CI на её
граничном коммите `8b7f741` по данным GitHub API завершился failure (установка
шлюза на Windows); следующая правка `e76dad1` — зелёная. Утверждение «проверено»
не называет прогон, поэтому проверить его нельзя.

Третье, мелкое следствие: `[Unreleased]` говорит о «двух карточках на доске», на
доске лежала одна.

## Обсуждение

2026-10-23: Найдено аудитом. Проверено чтением шапки/хвоста журнала, `git tag`,
`git log -- CHANGELOG.md` и GitHub API. Это кандидат на правку способа: правило
«запись о сверке называет прогон/коммит» и решение, что делать с историей
предыдущего поколения (пометка о границе поколений или отдельный файл).
Дописывать историю задним числом нельзя — журнал append-only; речь о правиле
на будущее и о явной отметке, где начинается текущая история.
