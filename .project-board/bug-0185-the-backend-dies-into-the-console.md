## Суть

Диагностика от владельца (2026-11-16) в порядке записи:

    startup: TorrSyncPlayer is starting (×2: 00:25:29 и 00:27:28)
    2026-11-16T00:27:37+03:00 Не удалось: /api/v1/torrents returned 500: {"error":"Internal server error"}
    2026-11-16T00:43:49+03:00 Добавлено: Jimmy Neutron Boy Genius 2001 Vekshin.ac3
    2026-11-16T00:50:31+03:00 Добавлено: Jimmy Neutron Boy Genius (2001) Fullscreen.mkv
    2026-11-16T00:56:48+03:00 Не удалось: DELETE /api/v1/torrents/648f7c382c...: context deadline exceeded

Строка `{"error":"Internal server error"}` — это ответ `Recovery`
middleware (middleware.go: «Panic in handler …»), то есть в бэкенде было
ПАНИК во время списка торрентов. Причина печатается в `logger.Error` —
а бэкенд, запущенный из GUI без консоли, печатает в stderr, который в
оконном процессе Windows ничей. Из-за этого:

- пользователь видел «500 Internal server error» без причины;
- в конце тот же бэкенд перестал отвечать вовсе (DELETE — context deadline
  exceeded), и в диагностике снова ничего не сказано, кроме времени;
- единственные логи, до которых человек может дотянуться (TorrSyncPlayer.log),
  заведомо не содержат строк бэкенда — они идут мимо них.

Ожидаемо: любой вывод встроенного бэкенда доезжает до того же файла, что и
остальная диагностика — пусть со своим префиксом, но в файле.

## Обсуждение

2026-11-16: Найдено в диагностике владельца. Нельзя починить причину, пока её
не видно; нельзя увидеть, пока она живёт в stdout/stderr дочернего процесса.
Исправление делается первым, причина ждёт по следам фикса в следующем живом
отчёте.
