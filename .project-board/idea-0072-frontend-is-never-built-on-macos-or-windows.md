## Суть

Цель обещает настольное приложение для Linux, macOS и Windows
(`CONCEPT.md#Границы проекта`), и это единственное место, где три платформы
зафиксированы. Проверяется это ровно на одной.

Что делает CI (`.github/workflows/ci.yml`):

- `build-backend` — матрица `[ubuntu, windows, macos]`, но это **бэкенд**,
  `make build` в `backend`;
- `test-frontend-go` — единственная джоба фронтенда, `runs-on: ubuntu-22.04`.

То есть Go-фронтенд на macOS и Windows не компилируется ни разу. Всё, что
может сломаться только на другой платформе, ломается молча: разделители в
путях, `dial_unix.go` / `dial_windows.go` в сокете IPC mpv, сборка Fyne с cgo
и GL-заголовками, поведение `fyne.io/systray`, упаковка пары «клиент +
бэкенд» из `frontend/cmd/build`.

`DEV.md#Сборка` честно говорит: «Кросс-компиляция с Linux на macOS и Windows
**не работает**… `GOOS=windows go build ./internal/...` собирает внутренние
пакеты и служит проверкой переносимости логики; сам бинарник собирается на
своей платформе». То есть способ уже признаёт, что доказать три платформы
можно только на своих машинах. `idea-0063` держит этот пункт открытым ровно
поэтому.

Что предлагается:

1. **Матрица сборки фронтенда в CI.** Три джобы `go build ./...` на
   `ubuntu / macos / windows`. Дёшево, ловит всё, что ломается при компиляции,
   и не требует ничего, кроме раннеров, которые уже используются для бэкенда.
   Не ловит: «собралось, но окно не открылось».
2. **Полная джоба тестов фронтенда на macOS и Windows.** `go test -race ./...`
   с `FYNE_DRIVER=offscreen`. Дороже по времени, и на macOS/Windows драйвер
   Fyne может вести себя иначе — но именно это и проверяется.
3. **Прогон на живой машине** — ручной, как уже делалось для Linux. Ничего не
   ловит автоматически, но доказывает «окно открылось и видео пошло».

Отдельно: вариант 1 ничего не говорит о том, открывается ли окно и работает
ли mpv. Окно между «собралось» и «пользуются» остаётся, и закрыть его можно
только живым прогоном — это стоит сказать прямо, а не считать зелёную
матрицу доказательством трёх платформ.
