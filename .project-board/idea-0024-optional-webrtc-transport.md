## Суть

Текущий ADR выбрал SSE-брокер через сервер. У этого решения цены: сервер видит метаданные просмотра (кто, где, что перематывает), квадратичный fan-out, комната умирает при рестарте сервера.

Multiplex использует weron (WebRTC P2P) — после ICE пиры обмениваются sync-сообщения напрямую. Преимущества:
- Приватность метаданных: сигналер видит только handshake, не sync-команды
- Масштабируемость: fan-out снимается с сервера
- Устойчивость: установленные P2P соединения переживают рестарт сигналера

Предлагаю добавить как **опцию** (`--enable-webrtc`), не ломая SSE:
- Встроенный сигналер на pion/webrtc (или опционально внешний weron signaler)
- Клиент (Qt) получает второй транспорт: data-channel для sync событий
- При включении: invite code получает 4-ю часть `key` (DTLS ключ комнаты)
- SSE остаётся фоллбеком для NAT, где WebRTC не пробивается

## Обсуждение

2026-10-09: Пользователь подтвердил как экспериментальную опцию. Условия из ADR пересмотра:
- Нагрузка на SSE fan-out (MaxSSEConnections) — WebRTC снимает
- Приватность стала обязательным требованием — WebRTC даёт E2EE для sync
- Появился signaler без эксплуатационной боли — встроенный pion signaler
- Требование переживать недоступность сервера — P2P переживает рестарт

Риски: сложность ICE/STUN/TURN, отладка "не соединились", macOS/Windows поддержка pion.
