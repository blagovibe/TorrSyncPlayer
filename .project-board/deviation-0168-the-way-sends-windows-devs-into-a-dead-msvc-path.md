## Суть

DEV.md, «Фронтенд — Go, Fyne и mpv» (Windows): «Go с go.dev и Visual Studio
Build Tools (компонент «Разработка классических приложений на C++»): без него
Fyne не соберётся». Проверено на живой машине (2026-11-14): Build Tools 2022
(VC.Tools.x86.x64 14.44.35207) и Windows SDK 10.0.26100 установлены, vcvars64
поднимается, `cl` запускается — и сборка падает на первом же cgo-пакете
(`# runtime/cgo`) с `cl: error D8021: invalid numeric argument "/Werror"`:
`runtime/cgo/cgo.go` тянет `-Wall -Werror`, которые cl отвергает как флаг
уровня предупреждений. Путь MSVC для этого стека мёртв, что согласуется с
тем, что CI на `windows-latest` явно ничего не ставит — там работает gcc,
который GitHub-раннер приносит с собой (у нас он не установлен:
`where gcc` пусто).

То есть человек, собравшийся по способу, получает красную сборку, а способ
обещает рабочую. Истина о тулчейне Windows живёт в образе раннера, а не в
способе.

## Обсуждение

2026-11-14: Найдено свежей сверкой. Проверено: `go env CC` → `gcc` (на машине
отсутствует), импорт-цепочка `frontend` → `internal/ui` собирается с
`CGO_ENABLED=0` (100 тестов зелёные), но `frontend/main.go` тянет
`fyne/v2/app` → `glfw` → `go-gl/gl` и без cgo не собирается вовсе. Лечение
(решение владельца): в способе — явная зависимость MinGW-w64 (MSYS2 или
choco `mingw`), с примером `PATH`, и ссылка на то, чем пользуется CI; либо
объяснить, как собрать с MSVC, если такой путь появится. Это правка способа
по правилу изменения, а не правка текста.
