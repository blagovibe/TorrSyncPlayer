## Суть

`ci.yml` держит `concurrency: group: <workflow>-<ref>` с `cancel-in-progress: true`:
каждый пуш в `main` отменяет прогон предыдущего. Два наблюдаемых последствия:

- прогон 43704374596 на `f342bce` (2026-11-15T10:30Z) отменён с «Canceling since a
  higher priority waiting request for CI-refs/heads/main exists» — HEAD ушёл без
  зелёного сигнала CI (CodeQL был зелёный, Long Gates — зелёный, CI — нет);
- третий macOS-замер сценария масштабирования 25 участников никогда не доходил до
  конца именно по этой причине (см. bug-0174), как и падающие плеерные тесты
  гасились конкуренцией (см. bug-0173).

`long-gates.yml` и `rendezvous.yml` живут с `cancel-in-progress: false` и своей
группой: их толпа не отменяет.

Решение владельца, 2026-11-15: для пушей в `main`/`develop` — `cancel-in-progress: false`,
для пушей в ветки pull request — оставить `true` (PR не копится в очереди).

## Обсуждение

2026-11-15: Найдено свежей сверкой (прогоны 43704374596 / 43704374650). Правка
вносится тем же коммитом, что и перенос живых плеерных тестов (bug-0173) и
сценария масштабирования (bug-0174): `concurrency` в `ci.yml` больше не зависит
только от ref — группа и `cancel-in-progress` различают `push` и
`pull_request`. Карточка закрывается после зелёного прогона на линии.
