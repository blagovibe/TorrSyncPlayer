## Суть

`frontend/cmd/build/main.go:87–96` собирает оба бинарника командой `go build -o`
без `-ldflags`, а дефолты лежат в `backend/internal/version/version.go:12–18`:
`Version = "dev"`, `Commit = "unknown"`, `BuildTime = "unknown"`. Этим скриптом
пользуются все три джобы `release.yml` (`:45`, `:186`, `:274`), поэтому
`/api/v1/version` в любом AppImage, zip и dmg отвечает `dev`.

Это регрессия относительно прошлого поколения: v1.1.5-я запись журнала
(`CHANGELOG.md:2033–2038`) прямо говорит, что все три платформы передают `-X`
ldflags, «чтобы `/api/v1/version` возвращал версию тега, а не dev». В Go-эпоху
`LDFLAGS` остались только в `backend/Makefile:22`, которым релиз не собирается;
Dockerfile собирает без версии тоже.

Почему это важно: без версии невозможна поддержка («какая у вас сборка»),
невозможно воспроизвести отчёт по коммиту, и весь расчёт DEV «отчёт будет про
названный коммит» держится на том, чего пользователь не видит.

## Обсуждение

2026-10-23: Найдено аудитом против способа. Проверено чтением
`cmd/build/main.go`, `release.yml`, `version.go`, `Makefile` и поиском `ldflags`
по репозиторию. Лечение: передавать версию/коммит/время в `go build` из скрипта
сборки (VERSION из тега или `dev`+коммит для локальной), плюс тест, что бинарник
не рапортует `dev`, и строка версии в окне/`/api/v1/version`.

2026-10-23: Правка написана. Скрипт сборки штампует бэкенд через `-ldflags`
(`versionPackage.Version`, `.Commit`, `.BuildTime`): версия — из `VERSION`
(префикс `v` срезается), коммит — из `COMMIT`, а собранный руками бинарник
остаётся `dev`, чтобы его нельзя было принять за релиз. Все три релизные джобы
передают `VERSION: ${{ github.ref_name }}` и `COMMIT: ${{ github.sha }}`.
Тесты: штамп доезжает до бэкенда и не доезжает до клиента, локальная сборка
остаётся `dev`, `-ldflags` действительно попадают в аргументы `go build`.
Прогон — за CI: в среде нет Go, карточка `in_progress`.
