## Суть

Сейчас пользователь должен: установить Qt6, libmpv, CMake, ninja, собрать фронтенд, собрать бэкенд. Multiplex распространяется через Flathub (авто-апдейты, sandbox).

Предлагаю:
- **Linux**: AppImage (включает Qt6, libmpv, бэкенд) — работает на любом дистре без зависимостей. GitHub Actions → AppImage → GitHub Releases.
- **Windows**: Winget манифест + GitHub Releases (MSIX/EXE инсталлер).
- **macOS**: .dmg (позже, если будет востребовано).

Flatpak — позже (требует манифест, портирование под portal API).

## Обсуждение

2026-10-09: Пользователь выбрал AppImage + Winget. AppImage проще Flatpak (не нужен портал, работает везде). Winget — нативный для Windows.

2026-10-14: **Посылка изменилась** (idea-0067: Qt снят, фронтенд на Go/Fyne).
Пользователю теперь не надо ставить Qt6, libmpv, CMake и ninja: нужен Go,
заголовки OpenGL/X11 и отдельный `mpv`. В AppImage соответственно уезжает mpv
и cgo-зависимости Fyne, а не Qt6 с libmpv. Суть карточки (нужны AppImage и
Winget, сейчас только сборка из исходников) не изменилась — изменился состав
того, что надо упаковать. Переписать раздел с зависимостями — часть работы
этой карточки, не молчаливая правка.

2026-10-14: **Форма для Linux решена владельцем: AppImage.** Карточка
переведена в `refining`: решение по одному пункту есть, по остальным — нет.

Что это меняет в постановке. Карточка перестала быть гипотезой и стала
блокирующей: `bug-0070` (релизный workflow собирает удалённое Qt-приложение)
нельзя починить, пока не решено, что пакуем, потому что `linuxdeploy-plugin-qt`,
`windeployqt` и `macdeployqt` к Fyne-приложению неприменимы. То есть
упаковка — не «когда-нибудь», а предпосылка того, что релиз вообще существует.

Открытые пункты, по которым нужны ответы владельца:

1. **Windows.** В карточке выбран Winget + GitHub Releases (MSIX/EXE).
   Подтверждать ли, или форма тоже меняется по ходу `bug-0070`.
2. **macOS.** В карточке помечено «позже, если будет востребовано».
   `bug-0070` требует решения и для macOS, иначе релизный пайплайн останется
   с мёртвой macOS-джобой.
3. **Что входит в пакет.** `mpv` внутри (AppImage/DMG растут, зато «работает
   сразу») или требуется на машине (README остаётся про `apt install mpv`).
   Второе дешевле и оставляет пользователю выбор версии mpv.
4. **Автообновление.** У Multiplex оно есть из коробки через Flathub.
   Для AppImage это отдельный `AppImageUpdate` и подпись ключом; для
   «просто AppImage» — нет.
