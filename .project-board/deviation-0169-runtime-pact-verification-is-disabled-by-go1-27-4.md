## Суть

`go1.27.4` (2026-11-10) сломал cgo-линковку `pact-go/v2/internal/native` на
`ubuntu-24.04`:

```
github.com/pact-foundation/pact-go/v2/internal/native: invalid linker input
file in #cgo LDFLAGS: .../_pkg_.a (unrecognized binary format)
```

Файл проявляется на любом входе, где пакет собирается с линковкой:

- `go test -tags contract` (джоба Contract Test) — FAIL;
- `go vet -tags contract` — FAIL внутри зависимости, до нашего кода;
- `go build -tags contract` — зелено (компиляция работает, ломается линковка);
- пакт-версии не виноваты: 2.5.1 и 2.9.0 ведут себя одинаково;
- образ runner'а (gcc) между зелёным и красным не менялся: менялся только
  тулчейн Go; 1.27.3 на той же картинке зелёный.

Это известное условие: go1.27.4 несёт security-фиксы для cgo и линкера, и этот
класс разрушения — цена, у которой пока нет опубликованного обходного пути и
нет Go 1.27.5.

## Что принято

- Рантайм Pact-проверка (джоба `Contract Test (Backend Provider)`) **удалена
  из CI** на время: постоянный красный учит игнорировать красный, а метод
  проекта это запрещает.
- Сторож против e2fb119-класса рота («конструктор провайдера разошёлся с
  тестовым вызовом») остаётся в другой форме: `go build -tags contract ./...`
  в Lint («Build the contract package») — компилирует пакет целиком и
  краснеет при рассогласовании сборки, но не исполняет интеракции.
- Снимок исходного расхождения: lint — зелёный на 1.27.4 (весь, включая
  build-guard), Test Backend с race и govulncheck — зелёный, тесты фронтенда
  — зелёные, включая Fyne; pact-верификация исполнения (реальные HTTP-интеракции
  провайдера) — НЕ выполняется.
- В `DEV.md` («Соглашения по тестам», `make test-all` запускает контракт)
  описание остаётся как было: на 1.27.4 `make test-all` упадёт на этапе
  сборки pact-пакета. Это дополняется карточкой, а не правкой способа —
  переход к работающему контракту — тоже карточка (сознательное решение
  владельца, 2026-11-14).

## Условия возврата (любое = проверить и снять карточку)

1. Выход go1.27.5 (или иного исправленного релиза): прогнать `go test -tags
   contract -run PactProvider ./internal/contract/` на той раннер-картинке —
   зелёный → вернуть джобу и эту карточку удалить.
2. Подтверждённый обходной путь внутри pact-go/свой FFI-билд, снимающий
   отказ: то же самое.
3. Ежемесячная перепроверка: жив ли ещё слом (прогон `go vet -tags contract`
   на эталонной картинке). Если go1.28 вышел и чинит это — см. п. 1.

Компромисс перепроверяется на каждой свежей сверке, как и остальные
`deviation: open`.

## Обсуждение

2026-11-14: Решение владельца по вопросу «оставить 1.27.4 с открытой
карточкой» против «отката к 1.27.3 с красным govulncheck» (GO-2026-6859,
net/http) — оставить 1.27.4. До этого: факт найден на живом прогоне (#543,
#544), root cause установлен чтением логов и релиз-нотов (go1.27.4: security
fixes to cgo/compiler/linker). Проверено локально: воспроизвести отказ тут
нельзя (нет C-тулчейна), воспроизводится и диагностируется только в CI.
