## Суть

`cmd/build` пишет `TorrSyncPlayer` (или `TorrSyncPlayer.exe`) — клиент — и
`torrsyncplayer` (или `torrsyncplayer.exe`) — бэкенд — в один каталог. На
файловых системах, нечувствительных к регистру (Windows, APFS по умолчанию),
это одна и та же запись: backend затирает client. Поэтому релизы Windows zip
и macOS DMG, начиная с первого, поставлялись **только с бэкендом** —
`torrsyncplayer.exe` по бандле = тот самый `TorrSyncPlayer.exe` ниже по
размеру, проверено v0.4.5 на живой машине: дело не в отсутствующем рантайме
(файл даже не содержал `fyne.io/fyne`), а в том, что клиента не было вовсе.
Окно ОС о libstdc++ в скриншотах пользователя — артефакт Fyne-сборки, который
существовал только у того, кто собирал сам; релизы сейчас такой сборки не несут.

## Обсуждение

2026-11-15: Найдено владельцем, подтверждено артефактом (открытие v0.4.5 zip:
11 файлов, ни одного клиента; `cmd/server` маркер в `TorrSyncPlayer.exe`;
запуск на живой машине = «Starting TorrServer»). Корень: `backendName()`
давал `torrsyncplayer[.exe]`, который отличался от клиента только регистром.
Исправление: `torrsyncplayer-backend[.exe]` на всех платформах; FindBackend
переобучается сначала на новое имя, затем на старые; релизный job копирует
новое имя; список ожидаемых файлов в проверке архива обновлён; удалённое
ононимание не прячется:оба имени теперь различаются не только регистром.
