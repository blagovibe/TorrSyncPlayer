# TorrSyncPlayer

[![CI](https://github.com/blagovibe/TorrSyncPlayer/actions/workflows/ci.yml/badge.svg)](https://github.com/blagovibe/TorrSyncPlayer/actions/workflows/ci.yml)
[![Release](https://github.com/blagovibe/TorrSyncPlayer/actions/workflows/release.yml/badge.svg)](https://github.com/blagovibe/TorrSyncPlayer/actions/workflows/release.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-yellow.svg)](https://opensource.org/licenses/MIT)

Настольный плеер для торрентов с синхронизацией просмотра между участниками
комнаты. Файл играет, не дожидаясь скачивания; друзья видят тот же момент в
той же секунде.

Что проект делает и зачем — в [CONCEPT.md](CONCEPT.md).
Как собрать, запустить и править — в [DEV.md](DEV.md).

## Возможности

- **Воспроизведение на лету** — старт без полной загрузки, остальное
  докачивается на фоне
- **Комнаты** — совместный просмотр без сервера: код приглашения несёт адрес
  хоста, и гость звонит прямо по нему, а команды идут напрямую по шифрованным
  стримам libp2p, а видео каждый тянет из торрент-роя своим собственным бэкендом.
  Участника зовут по имени из настроек; без имени его видно как «устройство …»
- **Доступ без аккаунтов** — токен доступа на процесс, сравнение за постоянное
  время, код приглашения `community:password:key:addrs` вместо паролей на сервере
- **Метрики** — Prometheus на `/metrics`
- **Буферизация** — приоритеты кусков торрента по позиции воспроизведения, для немедленного старта
- **Swagger** — интерактивная документация API на `/swagger/`

## Установка

Готовые сборки лежат на странице релизов:
[**Releases**](https://github.com/blagovibe/TorrSyncPlayer/releases). Качайте
файл под свою систему — `mpv` уже внутри, отдельно ставить ничего не нужно.

| Система | Файл | Как запустить |
|---|---|---|
| Linux | `TorrSyncPlayer-x86_64.AppImage` | `chmod +x TorrSyncPlayer-x86_64.AppImage` (один раз), затем двойной клик или запуск из терминала |
| Windows | `TorrSyncPlayer-windows-x64.zip` | распаковать и запустить `TorrSyncPlayer.exe` |
| macOS | `TorrSyncPlayer-macos-arm64.dmg` | открыть образ и перетащить приложение в «Программы» |

При первом запуске приложение спросит, где хранить куски торрентов: в
памяти (ничего не остаётся на диске) или на диске (загрузка продолжится
после перезапуска). Ответ применяется при следующем запуске и меняется в
настройках. Токен доступа приложение создаёт себе само — ни регистрации,
ни пароля.

Дальше: вставьте magnet-ссылку в поле сверху, выберите торрент, затем
файл — и он начнёт играть, не дожидаясь загрузки. Подробности — в
[«Как пользоваться»](#как-пользоваться).

### Сборка из исходников

Нужны Go 1.26+, заголовки OpenGL/X11 (для Fyne) и `mpv` в `PATH`:

```bash
cd frontend
go run ./cmd/build     # → dist/TorrSyncPlayer + dist/torrsyncplayer
./dist/TorrSyncPlayer
```

Клиент и бэкенд — неразделимая пара: каждый участник держит свой собственный
торрент-клиент, и приложение запускает его само на свободном порту.

Подробности сборки, флаги, systemd/launchd/NSSM и Docker — в
[DEV.md](DEV.md).

## Как пользоваться

**Посмотреть фильм.** Скопируйте magnet-ссылку и вставьте в поле добавления.
Торрент появится в списке; откройте его и выберите нужный файл. Видео начнёт
играть, как только наберётся достаточно данных — обычно через несколько
секунд, не дожидаясь конца загрузки. Дорожки звука и субтитры внутри файла —
в селекторах над списками; файл субтитров рядом с фильмом (`.srt`, `.vtt`,
`.ass`) — в селекторе «Файл субтитров», он подхватывается из раздачи сам.

**Посмотреть вместе.** Тот, у кого включено видео, открывает комнату
(«Создать комнату» рядом с «Войти», имя берётся из выбранного торрента)
и копирует код приглашения `community:password:key:addrs` одним сообщением.
Остальные вставляют код целиком в поле входа — каждый смотрит через свой
собственный бэкенд, чужой бэкенд никто не трогает вообще. Кто управляет
воспроизведением — тот хост; пауза и перемотка уходят остальным, и те
применяют их у себя. Если у кого-то кончатся данные, комната встанет на
паузу, пока его поток не восстановится, — сообщить о буферизации может
любой участник.

Комната собирается за секунды: код приглашения несёт адрес хоста, и гость
звонит прямо по нему. Если адрес не сработал — сменился адрес или сложный
NAT, — приложение само идёт вторым путём, через публичный DHT рандеву, и вот
этот путь стоит минут: скорость задаёт чужая сеть, а не приложение. Окно
показывает, каким путём вы соединились.

Перемотка у всех слегка различается по времени, но не расходится: приложение
подстраивает позицию плавно, а не рывком.

**Что защищено.** Код приглашения не даёт случайному человеку из интернета
смотреть с вами: транспортное соединение он открыть может, но handshake без
пары «пароль + ключ» не проходит — ни один стрим не открывается и ни одно
сообщение не слышно.
Код передают лично или по защищённому каналу — утекший код это зритель. Сам бэкенд закрыт токеном доступа, который
приложение генерирует себе при каждом старте; гостю чужой токен не нужен.
Регистрации нет, аккаунтов нет.

**Если что-то не работает.** Комната не открывается — проверьте код
приглашения целиком: четыре части, первые три через двоеточие, без лишних
пробелов, четвёртая — адреса хоста через запятую. Пиры не соединились —
смотрите блок состояния соединения под строкой комнаты: соединились ли, каким
путём — напрямую, через реле или через запасное рандеву, — сколько пиров рядом,
сколько напрямую, а сколько через реле, и ваш собственный ID. Запасное
рандеву задаётся в настройке «Запасное рандеву» и флагом `--bootstrap`; по
умолчанию это публичные ноды из списка проекта. Ошибки остаются в строке
событий внизу окна — опрос их не стирает. Видео не идёт — проверьте, что
`mpv` есть в `PATH` (`mpv --version`), либо укажите путь к нему в настройках;
без него приложение честно говорит об этом при выборе файла.

**Приложение молча умерло?** Если окно закрылось, а значок в лотке есть —
приложение продолжает работать: закрытие окна прячет его, а сам клиент и его
загрузка живут. Завершить по-настоящему — «Выход» в меню лотка. Без лотка
(`--no-tray`) закрытие окна завершает приложение.

## API

Интерактивная документация с примерами запросов — на `/swagger/` запущенного
сервера. Она генерируется из аннотаций в коде, поэтому всегда соответствует
реализации.

| Группа | Методы | Доступ |
|---|---|---|
| `/health`, `/api/v1/version`, `/metrics`, `/swagger/*` | GET | без токена |
| `/api/v1/torrents` | GET, POST | токен |
| `/api/v1/torrents/{id}`, `/files`, `/select`, `/magnet` | GET, POST, DELETE | токен |
| `/api/v1/torrents/{id}/buffer/position`, `/buffer/info` | GET, POST | токен |
| `/api/v1/torrents/{id}/stream` | GET | `X-Access-Token` (тот же заголовок, свой лимит) |
| `/api/v1/health/detailed` | GET | токен |

Комнат и синхронизации в HTTP API нет вовсе: команды идут не по HTTP,
а по шифрованным стримам libp2p между участниками, — их формы описаны типами
в `frontend/internal/rtc/protocol.go`. Подробности — в [DEV.md](DEV.md).

Регистрации и логина нет. Сервер генерирует один случайный токен при старте
(встроенному бэкенду приложения — через stdin, флаг `--token-stdin`;
вручную — флагом `--token`, тогда в лог он не печатается); клиенты передают
его в заголовке `X-Access-Token`. Флаг `--addr` задаёт адрес прослушивания
целиком, заменяя `:--port`.

`/api/v1/torrents/{id}/stream` проверяет тот же заголовок `X-Access-Token`,
что и остальные эндпоинты: `mpv` прикладывает его через
`--http-header-fields`, поэтому тикета в URL нет и больше не существует.
Сверх токена перед отдачей файла проверяется владение: человек, не
добавлявший этот торрент, его не получит.

## Ограничения

1. **Данные в памяти.** Куски торрента лежат в памяти (лимит `--memory-capacity`,
   максимум 256 ГБ), если не задан `--data-dir` с `--disk-storage`
2. **Нет базы данных** — реестр торрентов и владение пишутся в JSON-файлы;
   комнат и состояния синхронизации не хранит никто
3. **Прямые соединения.** Участники соединяются по libp2p напрямую (за
   сложным NAT помогает hole punching, а если не вышло — публичный релей).
   Окно показывает состояние соединения — соединились ли, каким путём, сколько
   пиров рядом, сколько напрямую, а сколько через реле. Запасной путь через
   публичный DHT стоит минут и зависит от чужой сети: он включается сам, когда
   адрес из кода не сработал, а его рандеву указывается в настройке
   «Запасное рандеву» и флагом `--bootstrap`
4. **Pact-потребитель на фронтенде** не реализован; контракт проверяется только
   со стороны бэкенда, а соответствие клиента ему — сценарными тестами против
   настоящего бинарника
5. **Кросс-компиляция с Linux на macOS/Windows не работает**: драйверу Fyne нужен
   cgo и нативный GL-тулчейн целевой платформы, собирать надо на своей платформе
