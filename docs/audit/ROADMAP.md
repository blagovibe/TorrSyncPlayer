## Главное, что нужно понять до начала работы

**Проект собирается, проходит тесты и имеет 94–100 % покрытия в половине пакетов — и при этом не работает как продукт.**

Это не парадокс и не небрежность. Это системный эффект трёх причин, которые вместе дали «зелёный» статус при полностью нефункциональном приложении:

1. **Контракт разошёлся, а моки закрепили баг.** Фронтенд ждёт «голый JSON-массив», бэкенд отдаёт конверт `{torrents, totalCount, …}`. Мок в `test_networkmanager.cpp` повторяет *неверный* контракт, поэтому тест зелёный ровно потому, что мок совпадает с багом, а не с сервером. Тест на пустое состояние `QVERIFY(m_manager != nullptr)` ничего не проверяет.

2. **Тесты проверяют самосогласовательность, а не корректность.** Тест стрим-тикета (`auth_test.go:157`) воспроизводит ту же сломанную формулу, что и продакшн-код, — две копии одной ошибки всегда согласованы.

3. **Ни одна проверка в конвейере не может упасть.** 6 Makefile-целей заканчиваются `|| true`, весь джоб `e2e-tests` и 4 из 5 шагов `sanitizer-tests` помечены `continue-on-error`. Зелёный CI не значит ничего.

Следствие: **процент покрытия и статус CI в этом проекте не являются сигналом качества.** Прежде чем писать новый код, нужно починить контур обратной связи — иначе следующий рефакторинг снова разорвёт сигналы незамеченным.

## План работ

### Этап 0 — Контур доверия (S, 1–2 дня, **делать первым**)

Пока конвейер не способен ломаться, любая следующая правка не защищена.

1. **Убрать `|| true` с 6 Makefile-целей** (`D-01`). Проверить, что `make test-all` действительно краснеет на сломанном коде.
2. **Снять `continue-on-error` с `e2e-tests` и sanitizer-шагов** (`D-02`). Ожидаемый эффект: всплывут реальные поломки — это и есть цель.
3. **Записать в AGENTS.md правило:** любая проверка обязана уметь падать. Запрет на `|| true` и `continue-on-error` без исключения в комментарии.

> Почему первым: без этого шаги 1–3 ниже будут чинить симптомы, которые конвейер снова не заметит.

### Этап 1 — Безопасность (S–M, 2–3 дня)

4. **Починить подпись стрим-тикета** (`B-01`) — `mac.Write(payload)` + `mac.Sum(nil)`. Перейти на непрозрачный тикет фиксированной длины (nonce + серверная карта) либо на JWT-подобный base64-payload + MAC, чтобы подпись несла только MAC.
5. **Переписать тест на проверку подделки, а не самосогласовательности** (`B-05`). Обязательные кейсы: изменённый payload, чужой `torrentID`, подделанная подпись, истечение, тикет от другого процесса. **Сегодня тест не ловит даже подмену подписи — она отвергается случайно, из-за длины.**
6. **Закрыть X-Forwarded-For** (`B-07`): `TRUSTED_PROXIES` по умолчанию доверяет любому приватному IP ⇒ обход rate limit и неограниченный рост карты ⇒ DoS по памяти. По умолчанию — не доверять ничему.

### Этап 2 — Продукт начинает работать (M–L, 1–2 недели, **критический путь**)

Порядок строго соблюдать: каждый следующий шаг бессмыслен, пока предыдущий не работает.

7. **`B-02` — убрать WriteTimeout для стриминга.** `ServerWriteTimeout = 0` для основного сервера (`main.go:171`) либо раздельные таймауты: короткий для API, нулевой для `/stream` и SSE. **Без этого п.8–10 проверять бессмысленно — соединение рвётся на 30-й секунде.**
8. **`B-03` — вернуть `http.Flusher` в `responseWriter`.** Добавить метод `Flush()`, пробрасывающий в underlying writer. Проверить отсутствие регрессии на маршрутах без SSE.
9. **`F-07` — убрать двойной лок.** Снять внешний `QMutexLocker` в лямбде `showEvent` либо заменить `m_mutex` на `QRecursiveMutex`. Дедлок инициализации блокирует всё остальное.
10. **`F-01` — начать наблюдать свойства mpv.** `mpv_observe_property` для `time-pos` (DOUBLE), `duration` (DOUBLE), `pause` (FLAG), `eof-reached` (FLAG) с проверкой кодов возврата. Обработчик уже написан — события просто не приходят.
11. **`F-04` — починить разбор конвертов.** `doc.object()["torrents"].toArray()` и `["files"].toArray()` + тесты на оба конверта.
12. **B-01 → `F-13` — перевыпуск тикета.** Тикет живёт 5 минут и не обновляется. Запрашивать заранее (~80 % TTL) и один раз перезапрашивать на 401/`MPV_EVENT_END_FILE`. Иначе после починки `B-02` фильм всё равно умирает на 5-й минуте.

### Этап 3 — Синхронизация комнат (M–L, 1–2 недели)

13. **`F-02`** — соединить `NetworkManager::roomCreated/Joined/Left` со слотами `RoomManager`, писать `m_currentRoomId`/`m_isHost`, ре-эмитить сигналы. Сегодня `isInRoom()` всегда `false`.
14. **`F-03`** — брать `roomId` из собственного запроса (`m_pendingJoinRoomId`), не из ответа; параллельно добавить `id` в ответ бэкенда и в `docs/API.md`.
15. **`F-06`** — вызвать `connectToSSE()` в ветке `CreateRoom`: хост сейчас не подписан на события и не видит эхо синхронизации.
16. **`F-05`** — роутить `type=="sync"` в `signalReceived`, читать позицию из `data.status.position` с фолбэком.
17. **`B-04`** — захватить `RLock` в `emitEvent` вокруг обхода `room.Peers`. Добавить тест, конкурентно дёргающий Join/Leave/prune — именно его не хватает, поэтому `-race` молчит.

### Этап 4 — Надёжность фронтенда (M, 1 неделя)

18. **`F-08`** — `reply->deleteLater()` в единой точке выхода (`qScopeGuard`), а не только в happy path. Сейчас 5 ранних выходов текут объектом.
19. **`F-09`** — retry-контекст хранить в самом запросе (`QHash<QNetworkReply*, RetryRequest>`). Глобальный `m_pendingRetry` при двух параллельных запросах повторяет **не тот** запрос — возможен дубль `POST /api/v1/torrents` или `DELETE`.
20. **`F-10`** — вынести `emit` из-под мьютексов; модальный `QMessageBox` заменить на неблокирующий status bar (дедлок GUI через reentrant event loop).
21. **`F-14`** — редактировать тикет из логов и текстов ошибок mpv (`[?&]ticket=[^&]+` → `?ticket=***`). Сейчас `qDebug()` печатает подписанный тикет в stderr, а Release-сборка не отключает `QT_LOGGING_RULES`.
22. **`F-12`** — разделить `test_asan`/`test_tsan` на отдельные таргеты: сейчас в одном два `main()`, линковка падает. Это тесты, которые должны были поймать `F-07` и `F-10`.
23. **`B-08`** — `Close()` внутри `closeOnce` (иначе повторный вызов паникует) и таймаут на `WaitForSSEConnections()` (иначе Ctrl-C виснет до 30 минут).

### Этап 5 — Доверие к тестам (M, 1 неделя)

Это то, что не даст следующему рефакторингу повторить сегодняшний день.

24. **Тесты против реального контракта.** Переписать `startRoomMockServer()` по фактическим ответам роутера; запретить мок-ответ, которого сервер не отдаёт. Это устранит главный механизм маскировки.
25. **Контрактный тест на конверты списков** — ловит возврат `F-04`.
26. **Покрыть `internal/torrent` (30.1 %) и `internal/storage` (37.9 %)** — приоритет: выбор кусков для старта воспроизведения, буфер, стриминг. Это ядро продукта, а покрыто хуже вспомогательных пакетов.
27. **Удалить мёртвый JWT-код:** 6 неиспользуемых констант (`JWTTokenTTL`, `JWTSecretLength`, `JTIBytes`, `JWTIssuer`, `JWTAudience`, `MinTokenLength`), структура `models.Claims`, секция `## JWT` из `.env.example`, `export JWT_SECRET` из рецептов, устаревшее утверждение в `SECURITY.md:38`.

### Этап 6 — Доведение до «идеала» (M–L, постоянно)

28. **`F-16` — плавный догон вместо рывка.** `CONCEPT.md` прямо обещает «при перемотке и изменении скорости догоняет плавно, с учётом задержки сети». Реализовано мгновенное `seek(position)`, контроля скорости нет вообще. Метод `SyncWithLatency` из `ARCHITECTURE.md` не существует. **Это единственное место, где продукт делает заявленное хуже обещанного.**
29. **`B-09` — health-чекинг врёт.** Ветка `p2pSvc == nil` — заглушка `_, _ = services, allHealthy`: упавший p2p рапортуется как `ok`.
30. **`B-10` — bcrypt под глобальным write-локом** блокирует все комнаты на ~250 мс на каждый вход с паролем.
31. **`F-17` — политика редиректов:** явно задать и проверять, что хост редиректа совпадает с сервером, иначе `X-Access-Token` утекает на чужой хост.
32. **`F-18` — self-signed TLS только для `localhost`.** Сервер из `USER_GUIDE` поднимают по LAN-IP ⇒ TLS не заработает в описанном сценарии.
33. **Точечная гигиена:** `.PHONY` для `test-ci`/`test-full`, `.gitignore` для `.pactlog_tmp/`, удаление `handlers.go.tmp`, `F-19` — `QMenu` без родителя, `F-11` — мёртвый `sendSignal()`, `F-15` — перехват любого `QEvent::User`.
34. **Документация сборки** (`D-08`): перечислить обязательные зависимости с версиями. Сейчас машину разработки нельзя собрать — нет `cmake` и Qt6.

    │

## Определение готовности

Проект можно считать готовым к релизу, когда одновременно:

- [ ] Фильм проигрывается **дольше 30 секунд**, перемотка работает, список торрентов непуст
- [ ] Комната: хост и участник видят одинаковый момент, перемотка догоняет плавно
- [ ] `go test -race` и `ctest` проходят, покрытие `internal/torrent` > 60 %
- [ ] Взлом тикета для чужого торрента **покрыт тестом, который падает на старом коде**
- [ ] `make test-all` и CI **краснеют** при искусственно внесённой ошибке
- [ ] ASan/TSan реально выполняются и блокируют merge
- [ ] Ни одного упоминания JWT в коде, конфигурации и документации
- [ ] `INSTALL.md` воспроизводим на чистой машине
