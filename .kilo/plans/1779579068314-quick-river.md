## Issues Found

### 🔴 CRITICAL (Fix Immediately)

#### C1. CSP `script-src 'self'` blocks inline event handlers
- **File:** `client/electron/main.cjs:130`
- **Issue:** The CSP header `script-src 'self'` forbids inline event handlers (`onclick`, `onerror`, etc.). While the current React codebase avoids them, this is fragile — any future inline handler will be silently blocked with no error in production.
- **Severity:** Critical — can break UI silently in production builds.
- **Fix:** Either add `'unsafe-inline'` to `script-src` (not recommended) or ensure all event handling uses `addEventListener` (current state is OK, but add an ESLint rule to enforce).

#### C2. `retry.ts` is unused dead code
- **File:** `client/src/utils/retry.ts`
- **Issue:** `withRetry` and `getBackoffDelay` are exported but never imported anywhere. The `P2PService.connect()` implements its own inline retry logic instead. Dead code increases bundle size and confuses contributors.
- **Severity:** Critical — dead code in production bundle.
- **Fix:** Remove `retry.ts` or integrate it into `P2PService.connect()`.

#### C3. `ErrorBoundary` is never used in the render tree
- **File:** `client/src/components/ErrorBoundary.tsx`
- **Issue:** The component is imported in `main.tsx` and wrapped around `<App />`, but the import is present and working. However, the `fallback` prop is never passed, so the generic "Something went wrong" UI is shown for all errors with no way to recover context.
- **Severity:** Critical — poor error recovery UX.
- **Fix:** Add a meaningful fallback with app name and reload button.

### 🟠 HIGH (Fix Soon)

#### H1. 885 kB single JS chunk — no code splitting
- **File:** Build output `dist/assets/index-DJiPGDvm.js` (885.54 kB)
- **Issue:** The entire app (including WebTorrent, PeerJS, React) is bundled into a single chunk. This means the initial load downloads ~885 kB (261 kB gzipped) before anything renders. No dynamic imports or route-based splitting.
- **Severity:** High — poor initial load performance.
- **Fix:** Add `React.lazy()` for route-based splitting (HomePage vs RoomPage). Use `build.rollupOptions.output.manualChunks` to separate vendor bundles (react, webtorrent, peerjs).

#### H2. `webtorrent.d.ts` type declaration conflicts with actual WebTorrent types
- **File:** `client/src/webtorrent.d.ts`
- **Issue:** The project has both a custom `webtorrent.d.ts` declaration AND WebTorrent ships its own types (via `@types/webtorrent` or bundled). The custom declaration may shadow or conflict with the real types, causing subtle type mismatches.
- **Severity:** High — type safety bypass.
- **Fix:** Remove custom `webtorrent.d.ts` and rely on the library's built-in types, or ensure they match exactly.

#### H3. `TorrentService` uses `any`-equivalent type assertions extensively
- **File:** `client/src/services/TorrentService.ts` — lines 46, 51, 69, 73, 100, 102, 139, 149, 159, 169, 178, 226, 331, 355, 400, 460, 481, 559, 625, 646, 696, 731, 773, 828, 847, 859, 887, 902, 927, 945, 996
- **Issue:** Heavy use of `as TorrentClient`, `as TorrentInstance`, `as EventKey`, and `unknown` casts. The `TorrentClient` and `TorrentInstance` types are hand-written interfaces that may drift from actual WebTorrent behavior.
- **Severity:** High — type safety is weakened throughout the core service.
- **Fix:** Import proper types from WebTorrent or use `typeof` inference from the actual client instance.

#### H4. `P2PService` reconnect logic has a state race condition
- **File:** `client/src/services/P2PService.ts:518-554`
- **Issue:** `attemptReconnect()` checks `this.state === "reconnecting"` to prevent concurrent reconnects, but after `this.peer.reconnect()` succeeds, it sets `this.state = "disconnected"` (line 547) before `this.connect()` can set it to `"connected"`. If `connect()` fails, the state is `"disconnected"` but `reconnectAttempts` was already reset to 0 (line 546), losing track of retry count.
- **Severity:** High — reconnection may silently fail or loop infinitely.
- **Fix:** Reset `reconnectAttempts` only after successful `connect()`. Use a proper state machine.

#### H5. Electron `before-quit` handler doesn't handle `torrentBridge.destroy()` rejection
- **File:** `client/electron/main.cjs:305-344`
- **Issue:** If `torrentBridge.destroy()` throws, the `forceExit` safety timeout still fires, but `hasExited` is never set to `true` because the catch block doesn't set it. This could cause `forceExit` to call `app.exit(0)` after the normal path already ran.
- **Severity:** High — potential double-exit crash.
- **Fix:** Set `hasExited = true` in the catch block before calling `forceExit()`.

#### H6. CI artifact path mismatch for Windows build
- **File:** `.github/workflows/build.yml:62`
- **Issue:** The Windows artifact path is `client/release/*.exe` but the `prepare-electron-app.cjs` script sets `output: "../release"` relative to `.electron-artifacts/`, meaning artifacts land in `client/.electron-app/../release/` = `client/release/`. This matches. However, the Linux path `client/release/*.AppImage` also matches. The issue is that `electron-builder` with `--projectDir .electron-app` outputs to `.electron-app/../release/`, which is `client/release/`. This is correct but fragile — any change to `prepare-electron-app.cjs` output directory will silently break CI.
- **Severity:** High — fragile CI configuration.
- **Fix:** Add a comment in both files linking them, or use a shared environment variable for the output path.

### 🟡 MEDIUM (Fix in Next Sprint)

#### M1. `App.tsx` is 1184 lines — too large for a single component
- **File:** `client/src/App.tsx`
- **Issue:** The main App component handles P2P initialization, torrent loading, sync, chat, room state, video playback coordination, and navigation — all in 1184 lines. This is a classic "god component" anti-pattern.
- **Severity:** Medium — maintainability.
- **Fix:** Extract custom hooks: `useP2PService()`, `useTorrentLoading()`, `useSyncService()`, `useRoomState()`, `useChat()`.

#### M2. `TorrentService` is 1015 lines — god class
- **File:** `client/src/services/TorrentService.ts`
- **Issue:** Handles WebTorrent client management, Electron backend bridging, stream URL management, buffer prioritization, blob fallback, service worker registration, and peer tracking — all in one class.
- **Severity:** Medium — maintainability.
- **Fix:** Split into `WebTorrentClient`, `ElectronTorrentBackend`, `StreamManager`, and `BufferPrioritizer`.

#### M3. No component/UI tests
- **File:** `client/src/components/` (6 components, 0 tests)
- **Issue:** `HomePage`, `RoomPage`, `VideoPlayer`, `StatusBar`, `RoomInfo`, `ConfirmModal`, `ErrorBoundary` have zero test coverage. Only the service layer is tested.
- **Severity:** Medium — regression risk for UI changes.
- **Fix:** Add component tests using Vitest + React Testing Library for at least `HomePage` (form validation), `VideoPlayer` (controls), and `ConfirmModal`.

#### M4. `TorrentService.test.ts` and `TorrentService.fixes.test.ts` share identical setup code
- **Files:** `TorrentService.test.ts:1-47` and `TorrentService.fixes.test.ts:1-47`
- **Issue:** The `vi.histed` mock setup and `createTorrent()` helper are duplicated verbatim across both test files.
- **Severity:** Medium — code duplication.
- **Fix:** Extract shared test utilities to `services/__tests__/test-utils.ts` or `services/__tests__/mocks/webtorrent.mock.ts`.

#### M5. `buildPeerServerOptions` accepts `PeerServerEnv` but `getImportMetaEnv()` returns `PeerServerEnv | {}`
- **File:** `client/src/services/P2PService.ts:106-108`
- **Issue:** `getImportMetaEnv()` returns `{}` as fallback, which means `buildPeerServerOptions` receives an empty object. The function handles this correctly (defaults kick in), but the type signature is misleading — it suggests all fields are potentially present.
- **Severity:** Medium — type clarity.
- **Fix:** Change return type to `PeerServerEnv` and cast once at the call site.

#### M6. `normalizeError` in `TorrentService` swallows error details
- **File:** `client/src/services/TorrentService.ts:1008-1012`
- **Issue:** `normalizeError` converts any non-Error value to a generic string. If WebTorrent emits an error object with additional fields (e.g., `error.code`), those are lost.
- **Severity:** Medium — debugging difficulty.
- **Fix:** Preserve original error properties using `Object.assign()` or spread.

#### M7. `SyncService` heartbeat doesn't account for video paused state changes
- **File:** `client/src/services/SyncService.ts:224-249`
- **Issue:** The heartbeat sends `state` messages every 2 seconds, but if the video is paused and the position hasn't changed, it skips sending (dedup logic at line 242). However, if the host pauses, the `onPause` handler fires and sends a `pause` message. Then the heartbeat's dedup check sees `stateChanged = false` (still paused) and skips. This is correct. But if the guest's local playback drifts (e.g., browser throttling), the heartbeat won't correct it because the position hasn't changed on the host.
- **Severity:** Medium — sync accuracy.
- **Fix:** Always send heartbeat when playing, even if position dedup says skip. Only dedup when paused.

#### M8. `P2PService` `sendPayload` sends to all connections when no target specified
- **File:** `client/src/services/P2PService.ts:675-690`
- **Issue:** When `targetPeerId` is undefined, `sendPayload` sends to ALL open connections. For a host with multiple guests, this is correct. But if a guest calls a send method without a target, it also broadcasts to all connections (which is just the host, so OK). However, there's no type-level guarantee that guests only send to the host.
- **Severity:** Medium — potential message leakage in future multi-peer scenarios.
- **Fix:** Add a `defaultTargetPeerId` concept for guests, or document the broadcast behavior.

#### M9. `RoomInfo` chat has no message limit or virtualization
- **File:** `client/src/components/RoomInfo.tsx:47-77`
- **Issue:** Chat messages accumulate in state with no limit. In a long session, this causes memory growth and DOM bloat (no virtualization).
- **Severity:** Medium — memory leak in long sessions.
- **Fix:** Add a message limit (e.g., last 200 messages) and use a virtualized list for large histories.

#### M10. `ConfirmModal` renders even when `isOpen` is false
- **File:** `client/src/components/ConfirmModal.tsx:48`
- **Issue:** The component returns `null` when `!isOpen`, but the `<dialog>` ref is still created and the `useEffect` still runs on every render. This is minor but wasteful.
- **Severity:** Medium — unnecessary renders.
- **Fix:** Move the `isOpen` check before any hooks, or use CSS `display: none` to keep the dialog mounted.

### 🟢 LOW (Nice to Have)

#### L1. `server/` directory is empty placeholder
- **File:** `server/README.md`
- **Issue:** The `server/` directory contains only a README saying it's reserved for future use. It adds no value and confuses contributors.
- **Severity:** Low — clarity.
- **Fix:** Remove the directory or add a `.gitkeep` with a clearer explanation.

#### L2. Root `tsconfig.json` includes non-existent `src/` directory
- **File:** `tsconfig.json:19`
- **Issue:** The root `tsconfig.json` has `"include": ["src"]` but there's no `src/` at the root level. The actual source is in `client/src/`. This tsconfig is never used (the client has its own), so it's dead config.
- **Severity:** Low — dead configuration.
- **Fix:** Remove root `tsconfig.json` and `tsconfig.node.json` since the client directory has its own.

#### L3. `vite-env.d.ts` is empty
- **File:** `client/src/vite-env.d.ts` (39 bytes, just a reference comment)
- **Issue:** The file only contains `/// <reference types="vite/client" />` which is auto-generated. It's fine but could include custom env type declarations for `VITE_PEERJS_HOST` etc.
- **Severity:** Low — developer experience.
- **Fix:** Add type declarations for custom Vite env variables (`VITE_PEERJS_HOST`, `VITE_PEERJS_PORT`, `VITE_PEERJS_PATH`, `VITE_PEERJS_SECURE`, `VITE_WEBTORRENT_TRACKERS`).

#### L4. `VIDEO_EXTENSION_PREFERENCES` gives `.mkv` and `.avi` preference 0
- **File:** `client/src/config.ts:71-80`
- **Issue:** `.mkv` and `.avi` get preference 0, which means they're sorted last. But `.mkv` is a very popular format for torrents. The comment says "browser-dependent" but the preference system doesn't account for the fact that `.mkv` may be the only video in many torrents.
- **Severity:** Low — user experience.
- **Fix:** Increase `.mkv` preference or add a note that auto-selection may pick unsupported formats.

#### L5. `bounded-chunk-store.cjs` LRU eviction is O(n)
- **File:** `client/electron/bounded-chunk-store.cjs:93-100`
- **Issue:** `_findEvictableIndex` iterates the entire `lruList` Set to find an index that isn't the current one. For large torrents with many chunks, this is O(n) per eviction.
- **Severity:** Low — performance.
- **Fix:** Use a proper LRU cache (doubly-linked list + Map) or evict the first element directly.

#### L6. `torrent-bridge.cjs` ffmpeg stderr logged even in test env
- **File:** `client/electron/torrent-bridge.cjs:830-835`
- **Issue:** The `NODE_ENV !== "test"` guard suppresses stderr logging in tests, but Vitest doesn't set `NODE_ENV` to `"test"` by default on Windows. This causes noisy test output.
- **Severity:** Low — test cleanliness.
- **Fix:** Check `process.env.VITEST` or use a logger instance instead of `console.warn`.

#### L7. `HomePage` join code validation is only length-based
- **File:** `client/src/components/HomePage.tsx:109`
- **Issue:** The join button is disabled when `joinCode.length !== 6`, but the code is not validated against the `peerIdChars` alphabet (`A-Z`, `0-9`). A user could enter `!!!!!!` and it would be sent.
- **Severity:** Low — input validation.
- **Fix:** Add regex validation `/^[A-Z0-9]{6}$/` and show an error for invalid characters.

#### L8. `StatusBar` buffer progress can exceed 100% in display
- **File:** `client/src/components/StatusBar.tsx:39`
- **Issue:** The buffer progress display uses `Math.min(100, Math.max(0, bufferingProgress))` for the bar width, but the text display on line 39 shows `bufferingProgress` directly (not clamped). If `selectedMediaBufferProgress` in App.tsx exceeds 100, the text shows >100%.
- **Severity:** Low — UI polish.
- **Fix:** Clamp the text display value too.
