# Full Project Audit — TorrSyncPlayer

## Project Overview
Electron + React desktop app for synchronized torrent-based video playback between peers via WebRTC (PeerJS). Uses WebTorrent for browser runtime and a custom Node.js torrent bridge for Electron runtime. Master/slave sync model with chat.

---

## Issues Found

### CRITICAL (must fix — security/correctness)

**C1. Endless reconnection loop when PeerJS `disconnected` fires during `destroy()`**
- `P2PService.ts:511-517` — The `onDisconnected` callback calls `attemptReconnect()` unconditionally even when `state === "destroyed"`. The guard at line 528 checks `destroyed` but not `disconnecting`. Also `this.peer.reconnect()` at line 557 on a destroyed peer will throw.
- **Fix:** Add `disconnecting` to the early-return check in `attemptReconnect()`.

**C2. `before-quit` handler race: `forceExit` can fire after successful cleanup**
- `electron/main.cjs:305-346` — If `torrentBridge.destroy()` resolves just after the 5s safety timeout fires `forceExit`, `hasExited` is already true but `clearTimeout` and second `forceExit` call pattern means windows get destroyed twice (double `win.destroy()`).
- **Fix:** Move `hasExited` flag check before the first `win.destroy()` loop, or use a proper cancellation pattern.

**C3. CSRF-like issue: IPC handlers lack origin validation**
- `electron/main.cjs:203-255` — `ipcMain.handle` for `torrent:addMagnet` and `torrent:addTorrentFile` validates types but not whether the calling webContents is from the app. If an XSS payload runs in the renderer, it can call these IPC channels freely.
- **Fix:** Validate `event.senderFrame` URL or add a shared-secret token for sensitive IPC calls.

**C4. Magnet link IPC allows DoS via memory exhaustion**
- `electron/main.cjs:204` — `magnetLink.length > 10000` check passes strings up to 10KB, but `torrentBridge.addMagnet` passes directly to WebTorrent which allocates buffers. Similarly `torrentFile` has no max size check on the IPC level.
- **Fix:** Add a max torrent file size (e.g., 10MB) and a stricter magnet length check.

### HIGH (should fix — bugs/reliability)

**H1. `enqueue` is misspelled → ReferenceError at runtime**
- `electron/torrent-bridge.cjs:46` — `ffmepgQueue.shift()` should be `ffmpegQueue.shift()`. This will throw a `ReferenceError` at runtime when the ffmpeg rate-limiter queue has >3 waiting tasks.
- **Fix:** Rename `ffmepgQueue` → `ffmpegQueue` everywhere (lines 46, 55, 773, 785, 969).

**H2. Missing `this._resolveAudioServerWaiter = null` in one destroy path**
- `torrent-bridge.cjs:324-327` — When `destroy()` sets `_resolveAudioServerWaiter = null` then `_resolveAudioServerWaiter(null)`, the waiter resolves to `null`, then `ensureAudioServer` throws. But `clearAudioSessions` at line 976 drains the queue without resolving pending tasks — they stay in-memory as unresolved promises.
- **Fix:** Reject or resolve all pending ffmpeg queue tasks in `clearAudioSessions()`.

**H3. `syncMessageTimestamps` map grows unboundedly**
- `P2PService.ts:745-756` — Timestamps are pruned per-peer but never cleaned up when peer disconnects. With many peers over time this leaks memory.
- **Fix:** Clear the entry on `peer_disconnected` event.

**H4. No `.gitattributes` → line-ending drift on Windows**
- Multiple files show `LF will be replaced by CRLF` warnings. Without `.gitattributes`, shell scripts (`.sh`) and cross-platform builds may break.
- **Fix:** Add `.gitattributes` with `* text=auto` and explicit `eol=lf` for `.sh`, `.cjs` files.

**H5. Uncommitted deleted source files without git tracking**
- `client/src/utils/retry.ts`, `client/src/webtorrent.d.ts`, `server/README.md`, `tsconfig.json`, `tsconfig.node.json` are deleted from disk but not `git rm`'d.
- **Fix:** Stage the deletions: `git rm` the deleted files.

### MEDIUM (should fix — code quality/maintainability)

**M1. `useRoomState` hook returns refs that should be managed by state**
- `hooks/useRoomState.ts` — 6 refs are shared across the component tree. Since refs don't trigger re-renders, ordering issues between `useCallback` closures and ref updates cause subtle stale-closure bugs (evidenced by 8 `react-hooks/exhaustive-deps` warnings that were suppressed).
- **Fix:** Convert to proper `useState` + context, or use a reducer.

**M2. 8 ESLint `react-hooks/exhaustive-deps` warnings suppressed**
- `App.tsx` lines 152, 190, 229, 282, 406, 796, 837, 938 — The dependency arrays are deliberately incomplete, which means the closures capture stale values. This is the root cause of multiple subtle bugs.
- **Fix:** Add proper dependencies or refactor to avoid the issue.

**M3. `TorrentService.clearActiveTorrentForAdd()` doesn't abort in-flight `addTorrentSource`**
- If `clearActiveTorrentForAdd` is called while `addTorrentSource` is still awaiting `prevQueue`, the old source continues processing. Only the *next* add call will see `isDestroyed`.
- **Fix:** Use an AbortController for the entire queue chain.

**M4. `RoomInfo` has no auto-scroll for chat messages**
- `RoomInfo.tsx` — New chat messages appear at the bottom but `chat-messages-scroll` div doesn't auto-scroll. Users must manually scroll to see new messages.
- **Fix:** Add `useEffect` scrolling `scrollTop = scrollHeight` on new messages.

**M5. `ConfirmModal` doesn't trap focus**
- `ConfirmModal.tsx` — Using `<dialog>` but not implementing focus trapping. Tab key can move focus outside the modal, violating accessibility.
- **Fix:** Add focus trap or use a proper dialog library.

**M6. Video player time display range input doesn't trigger `seek` on change while dragging**
- `VideoPlayer.tsx:369-372` — The seekbar's `onMouseUp`/`onTouchEnd` handlers fire `onSeek`, but if user uses keyboard arrows on the range input, seek doesn't fire until they release.
- **Fix:** Add `onChange` handler that calls `onSeek` directly (the current `setCurrentTime` already updates display).

**M7. `P2PService.bindConnection` doesn't remove PeerJS listeners on replace**
- If a new connection replaces an old one for the same peer (line 595-597), the old connection is closed but its PeerJS event listeners were registered via `conn.on` and are NOT removed — only the cleanup handles are.
- **Fix:** Close old connection before removing from map, or track and remove old listeners.

**M8. Chat messages have no sanitization**
- `RoomInfo.tsx:64` — `msg.text` is rendered directly via JSX which React escapes, but `msg.sender` is also user-controlled and rendered. While React escapes content, there's no length limit per message, no rate limiting, and no profanity/spam filter.
- **Fix:** Add per-message length cap (500 chars), per-peer rate limit, and consider server-side validation.

### LOW (nice to have — technical debt/style)

**L1. `TorrentService` and `P2PService` both implement custom event systems**
- Duplicate pattern: both have `listeners: { [K in EventKey]: Set<Callback> }`, `emit()`, `on()`. Should use a shared `EventEmitter` base or the `CleanupHandle.on()` pattern consistently.
- **Fix:** Extract a shared typed `EventEmitter` base class.

**L2. `electron/main.cjs` uses `require()` for ESM-only `webtorrent`**
- `torrent-bridge.cjs:542` — Dynamic `import("webtorrent")` inside CommonJS `.cjs` file works but mixes module systems. The whole electron side should be `.mjs` or the import should use createRequire.
- **Fix:** Rename to `.mjs` or use `createRequire`.

**L3. Inconsistent file extensions**
- Electron code is `.cjs` but vite config resolves `.ts` files with ESM imports. The `browser-polyfills.ts` file uses `import` but runs before Vite processes it in Electron context.
- **Fix:** Standardize on ESM for all JS/TS.

**L4. Missing `viewport` meta tag and mobile meta tags**
- `index.html` — No `<meta name="viewport">`, no theme-color, no PWA manifest. The app works in Electron only but the web version is broken on mobile.
- **Fix:** Add viewport meta, theme-color, description.

**L5. Service worker doesn't handle `activate` cleanup for old caches**
- `webtorrent-sw.js:36-38` — `clients.claim()` is called but old service workers aren't cleaned up. On update, old SW may still control some tabs.
- **Fix:** Add cleanup of old caches/clients in activate handler.

**L6. `App` component is 1162 lines**
- Massive component with mixed concerns: routing, state management, P2P logic, torrent logic, event handling.
- **Fix:** Extract into smaller components/hooks: `useRoomManager`, `useTorrentLoader`, `useP2PConnection`.

**L7. No test coverage for App.tsx, RoomPage, ErrorBoundary**
- Only service-level tests and a few component tests exist. No integration tests for the main App component, no test for ErrorBoundary behavior, no E2E tests.
- **Fix:** Add integration tests for critical user flows (create room, join room, load torrent, sync playback).

**L8. `package.json` `version` is duplicated**
- Root `package.json:4` has `"version": "0.1.12"`, `client/package.json:4` also has `"version": "0.1.12"`. These can drift apart.
- **Fix:** Remove version from root, or sync them via a shared config.

**L9. `index.html` has no CSP meta tag (only HTTP header CSP)**
- `electron/main.cjs:129-131` sets CSP via HTTP header, but `index.html` has no `<meta http-equiv="Content-Security-Policy">` fallback. If served without the Electron server (e.g., Vite dev), there's no CSP.
- **Fix:** Add CSP meta tag to `index.html`.

**L10. Removed `webtorrent.d.ts` breaks imports in test setup**
- `client/src/webtorrent.d.ts` was deleted (uncommitted). `vite-env.d.ts` now has its own `declare module "webtorrent"` but it's not referenced anywhere. Test files may fail if they import from `webtorrent` directly.
- **Fix:** Ensure `vite-env.d.ts` is included in `tsconfig.json` (it is by default since it's in `src/`).
