# TorrSyncPlayer — Full Project Audit Plan

## Summary

Comprehensive audit of the TorrSyncPlayer codebase covering all ~45 source files across client/ (React + TypeScript), Electron main process, services, components, utilities, tests, CI/CD, and configuration. Found **28 issues** across 5 severity categories.

---

## Issues Found

### 🔴 CRITICAL (Security / Data Loss)

**C1. Room password transmitted in plaintext over P2P data channel**
- `client/src/services/P2PService.ts:826` — `sendRoomConfig` sends `roomPassword` as a plain string field in the `room_config` message. The password is also stored in plaintext in React state (`client/src/App.tsx:57`).
- **Fix:** Do not send passwords over P2P at all; use a separate secure out-of-band share, or implement a challenge-response handshake.

**C2. `roomPassword` field is never actually enforced on the guest side**
- `client/src/services/P2PService.ts:487-494` — The `room_config` handler receives `roomPassword` and stores it in state, but `handleConnectToPeer` (`client/src/App.tsx:546`) never checks the password before connecting.
- **Fix:** Add a password prompt step for guests, verify against host, or remove the feature to avoid false sense of security.

**C3. No URL validation on magnet links beyond regex prefix check**
- `client/src/utils/torrent.ts:3` — The `MAGNET_LINK_PATTERN` only validates the `magnet:?xt=urn:` prefix. Arbitrary strings pass validation, including potential XSS payloads when rendered in UI.
- **Fix:** Add stricter validation of the infohash format (e.g., `[a-fA-F0-9]{40}` for v1, confirm base32 for v2).

**C4. `allowOrigins: "*"` in Electron torrent server**
- `client/electron/torrent-bridge.cjs:609` — `client.createServer({ origin: "*" })` allows any origin to access the torrent stream server, which serves local media files.
- **Fix:** Set `origin` to the specific `streamBaseUrl` instead of `"*"`.

### 🟠 HIGH (Bugs / Reliability)

**H1. P2PService `disconnect()` does not call `this.cleanup.abort()`**
- `client/src/services/P2PService.ts:849-871` — `disconnect()` clears connections and stop intervals manually, but never calls `this.cleanup.abort()`. This means timers and listeners registered via the cleanup handle survive the disconnect, causing potential leaks and stale callbacks firing on a "disconnected" service.
- **Fix:** Add `this.cleanup.abort()` at the start of `disconnect()`.

**H2. RoomPage `handleLeaveRoom` passed as `onLeaveRoom` but confirmation leaves immediately on confirm**
- `client/src/components/RoomPage.tsx:442` — The `RoomInfo` "Leave Room" button calls `onLeaveRoom` directly, which is mapped to `onShowLeaveConfirm`. But `RoomInfo` also receives `onLeaveRoom` which in App.tsx is the destructive `handleLeaveRoom` (which disconnects everything). The prop naming is confusing and dangerous — a future refactor could wire the wrong function.
- **Fix:** Rename props to `onLeaveRoom` (destructive) and `onRequestLeave` (confirmation trigger) for clarity. The current mapping in App.tsx:994 actually passes `onShowLeaveConfirm` to `onLeaveRoom` prop, but RoomInfo.tsx:113 uses `onLeaveRoom` destructively.

**H3. `useRoomState` hook is dead code — only `useRoomStateContext` is used**
- `client/src/hooks/useRoomState.ts` — Exports a ref-based state hook, but `hooks/index.ts` only re-exports it, and `App.tsx` imports `useRoomStateContext` instead. The ref-based hook and the context-based state diverge, creating two separate sources of truth for room state.
- **Fix:** Remove `useRoomState.ts` and `hooks/index.ts` (dead code), or consolidate into one state management approach.

**H4. Heartbeat interval and ping interval run concurrently with duplicated purpose**
- `client/src/services/P2PService.ts:744` — Ping/RTT check runs every 2s. `client/src/services/SyncService.ts:227-247` — Sync heartbeat also runs every 2s. Both generate network traffic. For a single host-guest connection, the sync heartbeat already serves as a liveness check.
- **Fix:** Increase ping interval to 10-15s or disable it for single-connection scenarios.

**H5. `syncToleranceSeconds` input has no upper bound validation in the UI**
- `client/src/components/RoomPage.tsx:319-326` — The tolerance number input has `min="0"` but no `max`. A user could enter 9999. The `sendRoomConfig` clamps to 30, but `setSyncToleranceSeconds` on the host side (`client/src/App.tsx:731`) accepts any value before sending.
- **Fix:** Add `max="30"` to the input and validate in `handleSyncToleranceChange`.

**H6. `npm run test` has a hardcoded Unix PATH that breaks on Windows**
- `client/package.json:18` — The test script sets `PATH=/usr/bin:/bin:/usr/sbin:/sbin:$PATH` which is invalid on Windows and will fail entirely.
- **Fix:** Remove the PATH override or make it cross-platform (use `cross-env` or a conditional script).

**H7. ESLint `no-explicit-any: error` rule is set, but `any` is used extensively in test files**
- `client/eslint.config.js:27` — The rule `@typescript-eslint/no-explicit-any: "error"` applies to `src/**/*.{ts,tsx}` which includes test files. Tests use `any` liberally (e.g., `vi.hoisted`, `mockReturnValue`). Either the rule is being violated in CI or tests are not linted.
- **Fix:** Add an ESLint override for `__tests__` and `*.test.*` files to downgrade `no-explicit-any` to `warn` or `off`.

### 🟡 MEDIUM (Technical Debt / Code Quality)

**M1. `server/` directory referenced in README but does not exist**
- `README.md:206` — Project structure lists `server/`. The directory is absent.
- **Fix:** Remove from README or create placeholder.

**M2. `onRoomPasswordChange` connected to raw input with no sanitization**
- `client/src/components/HomePage.tsx:129` — Password change passes `event.target.value` directly. No max-length enforcement on the input element (despite `maxLength={32}` being on a different field).
- **Fix:** Add `maxLength={32}` to the password input and trim the value.

**M3. `VideoPlayer.tsx` keyboard handler attached to `window` without cleanup on `canControlPlayback` change**
- `client/src/components/VideoPlayer.tsx:276-295` — The effect depends on `[settingsOpen, videoRef]` but the handler captures `canControlPlaybackRef`. The missing dependency causes stale closures.
- **Fix:** Add `canControlPlayback` to dependencies or ensure the ref pattern handles this (it does via `canControlPlaybackRef`, but the effect re-registers when `videoRef` changes unnecessarily).

**M4. No error boundary around `RoomPage` — only top-level**
- `client/src/main.tsx:10` — `ErrorBoundary` wraps the entire app. If `RoomPage` crashes, the entire app shows the error screen with a "Reload app" button, losing all state.
- **Fix:** Add a localized error boundary around `RoomPage` that allows returning to `HomePage`.

**M5. `TorrentService.destroy()` is async but called with fire-and-forget in multiple places**
- `client/src/services/TorrentService.ts:716` — `destroy()` is async. In `App.tsx:594`, `clearActiveTorrent()` is called with `await`, but `torrentServiceRef.current?.destroy()` at line 865 uses `.catch()` without awaiting the outer call.
- **Fix:** Ensure all `destroy()` calls properly await the full cleanup chain.

**M6. Duplicate constants between client and electron**
- `P2P_MAX_TORRENT_BYTES` is defined in `client/src/config.ts:28` as 10MB. `MAX_TORRENT_FILE_BYTES` is defined separately in `client/electron/main.cjs:260` as 10MB. Same limit, different constants, risk of divergence.
- **Fix:** Reference a shared config or at least add a comment cross-reference.

**M7. `VIDEO_EXTENSION_PREFERENCES` includes `.mkv`, `.avi`, `.ts` as recognized but not browser-supported**
- `client/src/config.ts:82-83` — `.mkv`, `.avi`, `.ts` are listed in `VIDEO_EXTENSIONS` and have preference scores, yet `BROWSER_SUPPORTED_VIDEO_FORMATS` in `TorrentService.ts:109-110` only lists `.mp4`, `.webm`, `.ogv`, `.mov`, `.m4v`, `.ts`. `.mkv` and `.avi` will fail in-browser with no native decode.
- **Fix:** Add clear user-facing messaging about format limitations. Don't score `.mkv` and `.avi` higher than `.webm`.

**M8. CI release workflow creates auto-tags that conflict with manual `v*` tags**
- `.github/workflows/build.yml:116-122` — The release job creates `push-${run_id}-${run_attempt}` tags, but triggers on `v*` tags. If a real `v*` tag is pushed, it will also create a `push-...` duplicate tag.
- **Fix:** Separate the auto-tag logic from the release logic, or skip auto-tagging when the ref is already a version tag.

**M9. `noUnusedLocals` and `noUnusedParameters` are enabled but tests and electron files violate this**
- `client/tsconfig.json:20-21` — Strict unused checks are on. The test mock at `P2PService.connection.test.ts:3` declares `peerInstances` but the `host`/`destroy`/`WT` hoisted mocks in `TorrentService.test.ts:4` include unused `createServerMock` and `destroyMock`.
- **Fix:** Verify these don't cause CI failures; if they do, fix the unused variables.

### 🔵 LOW (Minor / Style)

**L1. `getImportMetaEnv()` performs unsafe type assertion**
- `client/src/services/P2PService.ts:100-108` — `import.meta as unknown as { env?: Partial<PeerServerEnv> }` uses double-cast to access Vite env. The `vite-env.d.ts` already declares `ImportMetaEnv`.
- **Fix:** Import and use the typed `ImportMetaEnv` from `vite-env.d.ts`.

**L2. CSS uses `#eaeaea` in color scheme docs but actual CSS uses `#f3f5fb`**
- `SPEC.md:48` documents `Text: #eaeaea`, but `App.css:7` defines `--text: #f3f5fb`. Slight mismatch.
- **Fix:** Align spec with implementation or vice versa.

**L3. `buildCspHeader` allows `wss://*.peerjs.com` as wildcard, should be specific**
- `client/electron/main.cjs:73` — CSP uses `wss://*.peerjs.com` which allows any subdomain. PeerJS cloud is at `0.peerjs.com`.
- **Fix:** Use the exact hostname `wss://0.peerjs.com`.

**L4. `electronBuilder` build command uses `--publish never` in all scripts**
- `client/package.json:13-15` — All electron build scripts include `--publish never`. The CI workflow doesn't use `electron-builder` publish either.
- **Fix:** Remove redundant `--publish never` flag.

**L5. `RequestCredentials.omit` import is unused**
- `client/src/App.tsx` does not import `RequestCredentials` — actually checking the imports, this seems fine. But `client/src/services/TorrentService.ts:135` has `addQueue: Promise<void> = Promise.resolve()` which is a non-private, mutable field with no accessor.
- **Fix:** Make `addQueue` private.

**L6. `electron/bounded-chunk-store.cjs` does not handle `lastChunkLength` when `opts.length` is not provided**
- `client/electron/bounded-chunk-store.cjs:12-18` — When `opts.length` is undefined, `lastChunkIndex` is set to `Infinity`, and `lastChunkLength` falls back to `chunkLength`. The `put()` method checks `index === this.lastChunkIndex` which will never be true for `Infinity`, so the last chunk validation is effectively skipped.
- **Fix:** Track when length is finalized and compute `lastChunkIndex` accordingly.

**L7. No `.gitignore` or `.editorconfig` in project root**
- Missing from root. The client directory may have one, but the project lacks root-level ignore rules.
- **Fix:** Add `.gitignore` covering `node_modules/`, `dist/`, `release/`, `.electron-app/`, `*.AppImage`, `*.exe`.

**L8. TypeScript `downlevelIteration` is enabled but target is ES2020**
- `client/tsconfig.json:8` — `downlevelIteration: true` is unnecessary when targeting ES2020 which natively supports iteration protocols.
- **Fix:** Remove `downlevelIteration`.

## Architecture Assessment

**Strengths:**
- Clean service-layer separation (P2PService, SyncService,TorrentService) with well-defined interfaces
- Consistent use of AbortController-based cleanup pattern via `createCleanup()`
- Event-driven architecture with typed event buses
- Comprehensive test coverage at the service layer (6 test files)
- Reasonable security baseline: contextIsolation, sandbox, CSP headers, IPC validation
- Good TypeScript strictness settings

**Weaknesses:**
- Dual state management (useRoomState refs vs RoomStateContext) — pick one
- App.tsx is ~1050 lines — the central component is overloaded with state management, event handlers, and lifecycle logic. Extract into focused hooks.
- No integration/e2e tests for the core host-guest pairing flow
- Electron main process (torrent-bridge.cjs) is ~1044 lines in a single file — consider splitting into modules
- Test coverage gaps: RoomPage, App.tsx, and ErrorBoundary have no tests
- Service worker approach for WebTorrent streaming is fragile (requires HTTPS in production, depends on SW lifecycle)
